# 验证范围

## 已观察到

| 功能 | 证据范围 |
| --- | --- |
| SPP收音与WAV | 同一Mic 2上的多轮采集和用户试听；48kHz单声道解码 |
| BlackHole桥接 | 用户确认第三方软件可录到SPP音频 |
| MicBridge Audio | 驱动离线probe通过，Typeless能枚举并选中；不据此声称所有软件均通过长时间收音验收 |
| 退出SPP | 多轮12/65 ACK00→close；用户确认后续HFP录音清楚无断续，恢复期间可能闪断 |
| 固件查询 | 实机读取04.05.02.31 |
| 电量查询 | 05/06实机回复60%；自动首次查询和重复查询通过，当前周期配置120秒 |
| V2三种物理键 | 04/68独立事件，用户确认图标/箭头反馈；不再使用02/FF状态变化触发快捷键 |
| 临时按键模式 | 实测开启/关闭ACK，原短按动作被抑制；长按关机正常，重启恢复普通模式 |
| 降噪模式 | 热键模式内02/9F开/关均ACK00，02/A0回读正确；短按电源仍上报事件且不改变降噪 |
| V2普通退出 | 实机日志确认退出按键模式ACK先于关闭通道，未发送12/65；重开App恢复热键模式 |
| 电量协议测试 | 合成回复覆盖CRC/长度/地址/序号/0…100及无效值 |

0.4.2完整验证：130项Swift测试与63项Python诊断测试通过。安装包按架构检查实际payload与系统依赖。Apple Silicon已有本机实测，Intel交叉编译和包校验不能代替Intel实机验收。最新CI运行结果应优先于这里的历史计数。

## 未确定

- 不同Mic 2个体、固件和所有macOS版本的覆盖；其他Mic型号暂不支持。
- 仅有音频而没有可识别按键状态包的初始根因。一次重启后恢复，不代表根治。
- 音频序号缺口的全部来源。MicBridge容忍并计数，不保证缺口音质无影响。
- HFP/SPP并发冲突的全部路径；默认路由锁不能禁止应用直接打开DJI。
- 驱动桥接的广泛软件兼容性、长时间延迟/CPU/欠载基线，以及公开签名发行流程。
- HFP首次唤醒约3–4秒的问题。

离线测试不连接硬件。实机记录应分别注明连接方式、固件、接收端软件、时长、音频连续性、控制状态和用户试听结果；不要只凭“连接成功”判定完整验收。
