# MicBridge Mini 2 Demo

独立调试程序，面向 DJI Mic Mini 2 TX 02.03.17.00。与 MicBridge、原 Mic 2 Demo 使用不同 executable、Bundle ID 和日志目录。不会修改它们的连接偏好、热键设置或安装音频驱动。

## 当前路线：0.1.6 SPP 双热键

固件修改与刷写方案暂停。当前测试保持普通 SPP，不进入工厂按键模式，使用以下两项输入：

- **连接键单击**：经过校验的状态帧中 `capture=1`，每帧作为一次独立事件。
- **电源键双击**：通过连续状态帧的降噪开关变化推断；双击仍会改变实际降噪效果，并非独立原始按键报告。首次连接和断流恢复只同步降噪基线，不触发该热键；其他软件造成的降噪变化无法仅凭此状态位区分。

界面提供两行快捷键录入、计数及图标/箭头反馈；映射单独持久化，默认不发送。发送系统快捷键需要本 Demo 的辅助功能权限，未授权时仍显示事件计数。录入快捷键期间不发送热键。

Mini 2 **不提供软件降噪开关按钮**，只显示降噪状态。历史降噪调试实现保留在代码中，但当前 UI 没有调用入口。官方固件调试区默认折叠，当前流程不使用。

验证顺序：关闭 BLE 连接 → 刷新 SPP 列表 → 查询 SDP → 连接 SPP → 等状态就绪 → 单击连接键 → 双击电源键，核对两个计数分别增加一次。以下各版本章节保留历史调试流程，不代表当前默认操作。

## 构建与运行

在工程根目录运行：

```sh
bash scripts/build-mini2-demo.sh
open 'dist/MicBridge Mini 2 Demo.app'
```

脚本只构建 `Mini2Demo`，默认使用 ad-hoc 签名。可通过 `MICBRIDGE_SIGNING_IDENTITY` 指定本机证书 SHA-1；也可把 SHA-1 存在本机 `~/.config/micbridge/mini2-demo-signing-identity` 供后续构建复用，环境变量优先。证书配置不加入仓库。首次由 ad-hoc 改为开发签名仍可能需要授权，后续保持证书、Bundle ID 和路径一致。打开窗口不会扫描、连接设备或切换音频路由；首次点击扫描或刷新已配对列表时可能出现本 Demo 独立的系统蓝牙授权提示。

## 首轮硬件测试

1. 退出可能连接 Mini 2 的其他软件，其他接收设备保持关闭。打开 Mini 2。
2. 点击 **扫描**，明确选择 Mini 2 后连接 BLE。列表也可能出现其他广播设备，不自动连接任何设备。
3. 服务发现后，优先核对固件候选 `FFF0 / FFF3`（写入）和 `FFF0 / FFF4`（通知）。确认实际属性后点击 **订阅通知**；如果候选不出现，保留日志继续分析，不猜通道。
4. 点击 **查询版本**、**查询电量**。只有版本回应是 `DJI MIC MINI TX`、`02.03.17.00`，才允许进入按键测试。电量返回零填充时显示“数据未就绪”。
5. 先点击 **确认退出测试** 验证退出路径，收到准确回显 `00 43 01 08` 后，再点击 **进入测试 · 60 秒**。两个物理键各短按一次，观察 `KEY_1 / 06`、`KEY_PLAY / 07` 计数。逻辑键与机身按钮映射尚待实测。
6. 测试最长 60 秒，到时自动请求退出；手动断开 BLE 或退出 App 时，也先请求退出可能仍在运行的按键测试。只有匹配的成功 ACK 才视为退出确认。若 BLE 已丢失，须连接原设备确认退出；不能把失联当作恢复原按键功能。

TX 固件显示独立工厂按键报告固定走内部 UART，因此“进入 ACK 有效、计数一直为零”本身也是有用的结果。首轮版本没有系统快捷键发送；0.1.6 的降噪状态代理与工厂独立报告是两条不同路径。已实测 Mini 2 工厂模式会阻止普通长按关机，当前双热键流程不进入该模式。

## SPP 原始收包

- **刷新列表** 只列出已配对、名称含 Mini 的经典蓝牙设备；与 BLE 选择器需要选择同一台实物，程序不猜测两种蓝牙标识的对应关系。
- 所选设备已连上 Mac 后，点击 **查询 SDP**，从 `1101` 服务取得实际 RFCOMM 通道，绝不固定为 Mic 2 的通道 10。
- 点击 **连接 SPP** 后，代码锁定非 DJI 系统输入/输出，输入优先已有的 MicBridge Audio；不打开系统声音 UI、不启动 HFP 或输入电平。
- 接收过程中显示字节、外层封装、无线子块及丢弃字节数。它们是传输统计，不是音质、电平或独立按键成功的证明。序号缺口不会触发自动断开。
- 只有点击 **保存 WAV 与原始流 · 60 秒** 才保存音频相关原始字节，最多 60 秒，可提前停止；同时输出 `.bin` 和 48 kHz 单声道 `.wav`；按本次实机验证的 111 字节编码数据加零尾部布局解码，检查无线校验与帧类型。保存结束日志记录解码成功数、失败数及序号缺口；不自动播放。
- **关闭 SPP 通道** 只关闭本地 RFCOMM，不发 `12/65`，不调用系统蓝牙断连，不自动重连。
- **退出 SPP · 12/65**（0.1.4）仅在用户点击时发送 `01 + 本机蓝牙地址逆序`，收到匹配源/目的/序号、有效 CRC 的 `ACK 00` 后关闭本地 RFCOMM；超时或失败不自动重发、不当作成功。它清除该 Mac 的 SPP 重连记录，不写国家代码。音频默认路由保持在非 DJI 设备，不在退出时切回 DJI。

## 日志与边界

点击 **打开本次日志** 可查看 `events.jsonl` 与主动保存的 `.bin`，位于用户 Application Support 下的 `MicBridge Mini 2 Demo/Sessions/`。文件仅保存在本机；日志包含设备标识、原始控制回应，原始流可能包含声音，分享前应检查内容。

离线协议测试：`swift test --filter Mini2ProtocolTests`。测试使用合成帧，验证 CRC、分片、ACK 匹配、Mini 2 进入/退出参数、独立按键报告分类及可变 SPP 封装，不代表硬件兼容已通过。

各版本的指令范围见下述记录；0.1.5 增加限定官方包的同版本 OTA 调试，当前已暂停使用。没有全量配置写入、配对删除或任意命令输入。相关固件依据见 [Mini 2 固件分析](MIC-MINI-2-FIRMWARE.md)。

## 当前实测状态

2026-11-14 首轮已确认 BLE 版本、电量查询及按键模式进入/退出 ACK。有效窗口内两个物理键尚未产生可接收的独立事件。SPP 实测为 RFCOMM 12、MTU 666；本轮打开 SPP 会使 BLE 断开，关闭本地 SPP 后 BLE 可恢复。原始流序号连续，随后修正零尾部的截取规则，111 字节离线解码全部通过，后续 60.1 秒讲话录音也无解码错误和序号缺口，用户试听确认清晰。完整边界与证据见 [固件分析的实测章节](MIC-MINI-2-FIRMWARE.md#首轮实测2026-11-14)。

## 0.1.1 SPP 指令探测

连接 SPP 后点击 **验证 SPP 指令**，自动顺序执行时钟握手、结束时钟采样、版本查询、电量查询，单条回应等待最长 4 秒。仅内置这四项，不提供任意写入、不发送 `12/65`。只把匹配源/目的地址、命令、序号及有效内容的回应记为成功；时钟步骤 1 验证回应 `00 01`，步骤 2 验证 `00 02` 加 6 字节时钟数据；均须匹配请求序号。关闭通道前尝试清除仍开启的时钟采样。

SPP 实测：`12/58` 两步均有有效回应；`00/01`、`05/06` 本轮未收到匹配回应。SPP 可同时传音频及专用指令，不能据此认为 BLE 全部命令均可移用。


## 0.1.2 普通 SPP 连接键监听

保持工厂模式关闭，直接刷新已配对设备列表、查询 SDP 并连接 SPP。设备列表读取在后台队列执行，避免 IOBluetooth 初始化阻塞窗口。无需连接 BLE 或点击指令验证。

每个无线子块偏移 11 的状态字节重组成 22 字节状态帧，通过无线校验、状态 6 位校验和 CRC8 后，才将 capture=1 计作连接键事件。界面分别显示事件计数、降噪状态、有效状态帧、序号缺口、无效块和重复块。未点击保存时不落盘原始音频。

实机单次及三次间隔短按合计 4 次，均一一对应；电源键两次短按未增加 capture，也未改变状态或本体提示。具体证据与限制见 [按键策略实测结果](MIC-MINI-2-KEY-EVENTS.md#8-demo-012-实机结果)。

## 0.1.3 SPP 降噪测试

普通 SPP 状态更新后，可点击“开启降噪”或“关闭降噪”，发送无线 `19/11`，不使用 BLE 或工厂模式。写入成功不是执行确认；等待至少 300 ms，再以连续三帧有效目标状态确认，6 秒超时不重发。同值按钮禁用，避免把未变化的状态误称为命令有效。测试相反状态后手动恢复起始状态。

电源键应快速双击；黄色降噪灯与协议降噪位一起核对。降噪变化不计作独立电源键事件。关闭连接会取消未完成验证，不自动更改降噪设置。

实测已通过 `19/11` 开启、关闭及物理电源双击的状态更新，最后恢复降噪关闭。详见 [0.1.3 实测记录](MIC-MINI-2-KEY-EVENTS.md#11-demo-013-spp-降噪实测2026-11-14)。

## 0.1.4：12/65 单次退出实测（2026-11-14）

用户要求先退出 SPP，再确认原生系统输入，最后测试 BLE/HFP 共存。旧 0.1.3 只具备本地关闭功能，首次关闭未收到确认；结束旧进程后，用同一本机开发签名替换 0.1.4，重新连接 RFCOMM 12。本轮没有开始 BLE 扫描、HFP 录音或工厂按键模式。

17:31:18（本地时间）用户授权的 `12/65` 单次请求收到匹配回应：`55 0E 04 66 3A 02 01 02 80 12 65 00 69 B9`，序号 `0x0201`，payload `00`，CRC 有效。随后 Demo 关闭本地 SPP，界面及日志均确认“SPP 通道已关闭”，没有主动调用系统蓝牙断连或自动重连。

此结果确认该请求和通道关闭顺序；原生 HFP 音频是否恢复仍等待用户检查，BLE/HFP 并存也尚未验证。协议测试 17 项通过，包含地址逆序、匹配 ACK、错误返回码/长度/CRC 与错序号拒绝。

## BLE 与原生输入电平并存观察（2026-11-14）

12/65 ACK00 并关闭 SPP 后，用户先确认系统原生输入电平正常。随后仅连接 BLE FFF0 控制服务、订阅 FFF4，读取版本 `02.03.17.00` 与电量 `65% / 4017 mV` 均收到有效 DUML 回应；ATT 写入层仍有历史上已见的 Unlikely error，未阻止匹配协议回应。状态通知持续到达，观察期间未出现 BLE 断开记录，未重新打开 SPP、未进入工厂模式。

用户在 BLE 已连接后再次观察并明确确认：选择的是 DJI Mic Mini 2 原生输入，电平仍正常。本轮据此记录为 BLE 配置/通知与原生输入电平观察共存通过。后台 CoreAudio 采样未捕获 DJI running，默认输入快照读到 MicBridge Audio；该辅助采样未能独立证实 HFP 活动，不能把它写成机器侧并行录音验证。未保存 HFP 音频，也未验证长时间录音连续性。读数与通知证据保存在 ignored `work/mini2-ble-hfp-coexist-20261114/` 及 Demo 会话日志。

## 0.1.5：官方同版本 OTA 调试

本地 Demo 新增专用 BLE OTA 控制，仅接受 SHA-256 固定的官方 02.03.17.00 合包，直接截取原始 TX AOTA 模块；不重压缩、不修改固件、不传 RX、不支持任意文件或降级。原包不随源码分发。

操作顺序：加载官方原包 → BLE 连接/订阅 → 查询版本和电量 → 确认退出工厂按键测试 → 关闭 SPP、关闭 DJI 原生音频采集 → 开始官方同版本平刷。要求 120 秒内回读到 02.03.17.00 和至少 50% 电量。设备保持供电，不操作按键或断开连接。Demo 阻止传输期间关闭 App 或同时发普通控制命令，并抑制 Mac 空闲睡眠。

传输独立使用 E49A25F8 / E49A25E0 / E49A28E1 OTA 服务，按设备请求的偏移和长度返回带 CRC32 的数据块，ATT write-with-response 串行提交。设备重发范围时重新从 PSN 0 开始，不做主机猜测重试。收到设备 cmd 06 校验结果后发送 Mimo 同款空 cmd 06 ACK；这一状态仅标记“设备镜像校验通过”，仍需重连回读版本和核对基础功能，不用同版本号本身冒充刷写证据。

离线验证：21 项 Mini2ProtocolTests 通过；另执行原固件 Thumb 数据接收/CRC 指令的 18 项仿真检查（流读取与日志调用被 stub，不是完整硬件仿真）。截至本段添加时尚未实机发送 OTA 请求。

实机补充：2026-11-14 已完成一次 02.03.17.00 官方同版本平刷，最终设备校验成功、重启后 BLE 固件和电量回读正常，详见 `MIC-MINI-2-FIRMWARE.md` 的同版本实测结果。当前进度条为整个 AOTA 字节覆盖率（本轮约 99.35%，因设备未请求引导文件与填充），不能替代设备最终校验结果。
