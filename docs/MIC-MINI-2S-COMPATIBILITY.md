# Mic Mini 2S：SPP 音频与独立按键模式研究

研究日期：2026-11-15。对象为 DJI 官方 `dm203` TX 固件 `30.01.06.01`，发布版本 `30.01.0601`。本轮仅进行解包、静态分析和原始 Thumb 指令离线执行；没有使用 Mini 2S 硬件，没有修改或刷入固件，也没有为 MicBridge 宣告已支持此型号。

## 结论与适配路线

| 路线 | 固件证据 | 尚需验证 |
| --- | --- | --- |
| 普通 SPP 收音 | 存在 48 kHz、240 采样点/帧的 LC3 路径，新版音频封装 | 实际采集、解码、连续录音和丢包情况 |
| 普通 SPP 连接键单击 | 直接上报 capture 事件，TLV tag `0F` | 实机事件数量、延迟、去重 |
| 普通 SPP 电源键双击 | 切换降噪，并有降噪状态 TLV tag `0E` | 状态变化作为热键代理；不是原始按键事件，软件设置也可能触发 |
| BLE 独立按键模式 | 两个单击分别产生 `04/68` 独立事件，路由可到 BLE `FFF4` | 真机进入/退出、事件上报、HFP 共存和长按关机 |
| BLE 独立按键 + SPP 音频 | SPP 连接安排约 2 秒后主动断开 BLE | 当前不能作为可靠组合；未找到普通 SPP 上的独立按键回传出口 |

Mini 2S 的独立按键模式值得单独验证。其事件返回地址来自请求发送方，区别于此前 Mini 2 工厂按键研究中的固定 UART 路径。优先候选是 **BLE 按键模式 + 系统原生蓝牙输入**，但不能把 Mini 2 上的 HFP/BLE 共存实测结果直接认作 Mini 2S 已验证，也不能承诺原生输入具有 SPP 的 48 kHz 采样率。

## 独立按键模式：返回路径能够到 BLE

### 命令与按键分支

`04/68 → 0x10028F58` 的子操作 `43` 使用以下 payload：

| 操作 | Payload | 成功回应 payload |
| --- | --- | --- |
| 进入独立按键模式 | `43 01 00` | `00 43 01 00` |
| 退出独立按键模式 | `43 01 08` | `00 43 01 08` |

进入时，`0x1002901A` 读取请求的发送方地址 `packet[4]`，存入 RAM `0x21046BCA`；退出时清零。它不只是布尔值，而是后续事件的接收地址。离线检查覆盖发送方 `02` 和 `2B`，两者均被保存，但后续传输路由不同。

- 连接键单击 `0x10007A94`：模式非零时调用 `0x100ACAD2(mode, 6)`，跳过普通 capture 操作。
- 电源键单击 `0x10007B88`：模式非零时调用 `0x100ACAD2(mode, 7)`，跳过普通录音开关操作。
- `0x100ACAD2` 生成 `04/68` 独立事件，payload 分别为 `00 43 01 06`、`00 43 01 07`。这是离散按键事件，不依赖音量或降噪状态变化。

### 从事件到 BLE 的完整路径

1. `0x100ACAD2` 将保存的地址放进事件接收方字段，调用 `sc_comm_send (0x1009CA44)`。
2. `0x1009C9E0` 查询 ROM 路由表 `0x100CB318`：地址 `02` 对应 link 2；`2B/5A/0A/4A` 对应 link 1。
3. link 表 `0x100CB340`：link 2 为 HAL 类型 5，link 1 为 HAL 类型 0。当前表中没有 SPP HAL 条目。
4. `0x100BE3EE` 将 HAL 5 分派给 `hal_vport_tx (0x1009C794)`；HAL 0 则走另一 UART 路径。
5. BLE 连接回调在 `0x10099134` 注册 `vport_tx_on_ble (0x1009C94C)`；BLE 断开时在 `0x10098EC8` 取消注册。
6. `vport_ble_tx_process (0x1009C8AC)` 消费发送队列，经 `0x100A81F0 → 0x1005B9E0` 发出 **FFF4 notification**。

因此，后续 Demo 应验证 **以发送方 `02` 进入模式并订阅 FFF4**，不能沿用一个会把事件导向 UART 的发送地址。已有离线检查覆盖路由选择、事件 payload、HAL 分派及最终 FFF4 端点；未仿真整个蓝牙栈或实机通知。

### 原功能与退出边界

- 模式只在两个单击分支中被读取。电源键双击仍可能切换降噪，连接键双击仍可能切换工作模式；离线对比模式 0/2 的结果相同。因此不应把 UI 描述为“禁用所有原按键功能”。
- 普通电源单击本来受录音按键配置控制；测试模式在这些检查之前就发送独立事件，不需要先启动本地录音来捕获单击。
- 长按路径没有读取该模式标志。但 `key_power_process` 返回的 `0x2A` **不是关机事件**，其后映射到通话拒接逻辑，不能用它证明可关机。
- 实际电源管理另有按住时长计数，`0x10032914…0x10032962` 中出现超过 `0x708` 毫秒后的 `KEY POWER OFF` 分支。此处未见该独立模式标志的拦截。完整硬件关机行为仍需实测，尤其应避免将 Mini 2 的“测试模式无法关机”直接套用到 Mini 2S。
- 已检查的 BLE 断开分支仅注销传输回调，未见清除 `0x21046BCA`。掉线后有可能继续接管单击却无法把事件送到主机。Demo 应有明确退出、重新连接后恢复的流程，不能把主机倒计时结束等同于设备已退出模式。

## SPP：48 kHz 有明确配置，但不是旧 Mini 包格式

`spp_audio_player_start (0x10011C6C)` 传入 `media_player_open (0x10051E38)` 的参数如下：

| 参数 | 数值 |
| --- | --- |
| 编码格式字段 | `22`，对应这条 LC3 路径 |
| 输入/输出采样率字段 | `48 / 48` |
| 样本位深字段 | `24`；不表示无线传输是无压缩 PCM |
| 帧采样点数 | `240`，对应 48 kHz 下 5 ms |
| 码率字段 | `0x2BC00 = 179200 bit/s` |
| 声道配置 | 根据音频策略返回值选择 1 或 2；不能仅靠静态代码断言实机固定双声道 |

采集服务 `0x10055566/0x1005556E` 接收两项采样率；编码器参数路径 `0x10056776/0x10056780` 调用 `0x10052CC4`，将 `48` 转为 `48000`，供 DSP 参数使用。SPP 应用类型 `0x2B` 在 `0x10056868…0x10056880` 使用原始 bit/s 码率，覆盖其他编码路径的 ×1000 转换。

`spp_audio_lc3_data_pack_protocol_process (0x100111E0)` 每次读取 112 字节编码数据，经 `0x10003FCC → 0x1000236C` 包装：

- 4 字节头：长度 `116`、6 bit 加和校验、类型 `10`、递增序号。
- 112 字节音频数据。
- 6 字节时间戳。
- 合计 122 字节；在新版 SPP 中再加子包头及外层 `AA…A5` 封装。

这不是现有 Mini 1/2 的 `55 77 05` 布局。不能把 Mini 2S 简单加到旧型号枚举，或继续剥掉一个字节后送入固定 111 字节解码器。112 字节与 5 ms、179200 bit/s 数值吻合，但最终 LC3 解码和声学连续性仍需要真实音频样本确认。

### 普通 SPP 的按键相关状态

连接单击正常路径调用 `wl_protocol_update_tx_capture_event (0x10003AE4)`，产生 `0x19` 类型状态包、tag `0F`、长度 1、值 1。序号 0 时，原固件离线输出为：

```text
状态包：07 2A 19 00 0F 01 01
SPP 包：AA 40 0A 01 80 07 07 2A 19 00 0F 01 01 A5
```

降噪更新 `0x100038EE` 使用 tag `0E`。电源双击在允许降噪按键的条件下提交设置事件 `0D`，因此可以研究“降噪状态变化 → 电源双击热键”的旧方案，但这仍是代理事件，软件或其他来源改降噪必须排除。电源单击的录音状态变化也不是纯按键事件，不宜为了热键而开启本地录音。

### BLE 与 SPP 共存的固件限制

- `_spp_audio_init` 在 `0x1000FAB2…0x1000FAB8` 将 context `+0xD0` 的延迟任务绑定到 `0x100A86FE`。
- SPP 连接处理器 `0x100102D0…0x100102D8` 将该任务安排在 **2000 ms** 后运行。
- `0x100A86FE` 直接调用 `bt_manager_ble_disconnect (0x1009930C)`，参数 0 表示走断开全部相关 BLE 连接的分支。
- 初始化等待 LE Audio 离线时也会在 `0x1000FBA8` 调用此断开函数。
- 已检查的普通 SPP 接收分派没有直接通向 `04/68` 通用命令处理器，独立事件返回路由表也未提供 SPP 条目。

所以不能仅凭“SPP 和 BLE 在蓝牙规范上可以共存”推断本固件允许它们稳定共存。也没有证据表明改一个请求发送方地址，就能把 BLE 的独立事件转到普通 SPP。

## 离线验证与下一轮硬件验证

本机研究目录 `work/mini2s-firmware-20261115/` 保存下载校验、解包结果、反汇编以及 `audit_spp_keys.py` / `spp-keys-audit-results.json`。36 项检查使用官方程序的原始指令，外部日志、消息队列、音频服务和蓝牙出口使用明确替身；覆盖模式进入/退出、两个单击、两个双击、长按分派、地址路由、FFF4 出口、音频配置/打包、状态封装和 SPP 延迟断开 BLE。

建议实测顺序：

1. 只连接 BLE，确认型号/版本及 FFF4 通知；以发送方 `02` 进入独立按键模式。
2. 两个键各单击一次，验证恰好收到事件 6/7，且不触发原单击功能；退出后验证原功能恢复。
3. 再进入模式，验证长按关机，并核对重启/断开重连后的模式状态。
4. 保持 BLE 和系统原生输入持续采集，检查按键事件、音频稳定性及协商采样率。
5. 单独测试普通 SPP 新封装、48 kHz 解码、连接键事件与降噪代理事件；与 BLE 路线分开记录结果。

相关增益研究见 [Mini 系列音频设置对照](MIC-MINI-2-AUDIO-SETTINGS.md)。在完成上述验证前，不修改生产版的支持列表，也不把 Mini 2S 标为已兼容。
